# Multi-FPGA architecture

## 1. Layers

The project has three layers. The upper one does not know the lower one, and each link between layers is an interface contract with defined ports, handshake and latency.

| Layer | Content | Written by | Knows the board? |
| :--- | :--- | :--- | :--- |
| 1. SoC | Core, caches, routers, arbiters, interconnect, CLINT, PLIC and peripherals, gathered in the `soc` entity ([../soc/soc.md](../soc/soc.md)) | People, in VHDL | No |
| 2. Backends | One realization per memory region and per I/O resource, chosen in the `platform.yaml` | People (backend RTL) and the Tools (instantiation) | Only what the chip imposes (width and timing), coming from generics |
| 3. Board package | Device, clocks, pins, chips, capacities and IDCODE | Data (`board.yaml`, `pins.yaml`, family and chip) | Yes, and only here |

The link between layers 2 and 3 is a thin top generated by the Tools ([geracao.md](geracao.md)), which instantiates the SoC, the chosen backends, the PLL and the pin ring. No hand-written RTL cites a pin, family or vendor, except the wrappers of vendor primitives, which live in folders named after the vendor.

Each piece of data has one owner and exists once.

| File | Describes | Where it lives |
| :--- | :--- | :--- |
| `platform.yaml` | What the SoC asks for: map, profile, backends, clocks, I/O, console | `src/<group>/<platform>/` |
| `board.yaml` and `pins.yaml` | What the board offers and where the pins are | `boards/<board>/` |
| Family | What holds for every device of a family | `boards/families/` |
| Chip | Timing and organization of a memory chip | `Memory/chips/` |
| Calibration | Measured cost of each SoC block in the family | `boards/calibration/` |

The schemas are in [formato.md](formato.md), [familias.md](familias.md) and [plataforma-e-placa.md](plataforma-e-placa.md).

## 2. Regions and backends

The `platform.yaml` describes resources in four groups, and each resource has a backend.

| Group | Resources | `emulado` backend | `dispositivo` backend |
| :--- | :--- | :--- | :--- |
| Boot | `BOOT_MEMORY` | FPGA memory block with initial image (only backend) | Does not exist |
| Program storage | `FLASH` and its banks | Dual-port memory block behind the chip model, with configurable latency | Parallel NOR FLASH, FPGA internal FLASH, serial FLASH |
| Data | `RAM` | FPGA memory block | SDRAM with width by generic, asynchronous SRAM |
| I/O | Console, switches, keys, LEDs, displays | Simulation model, or absent | Board pins, JTAG UART |

The `on_bus` field of a `memory` segment says whether it sits behind the external port of the core, and `type` says how it is realized (`emulated` is the `emulado` backend, and `flash`, `sdram` and `sram` are the `dispositivo` backend). The `emulado` backend has two targets: in simulation it is the VHDL chip model, of any size, and in the FPGA it is an internal memory block, limited by the RAM inside the board (section 6).

| Backend | Region | Contract | Board resource (`needs`) |
| :--- | :--- | :--- | :--- |
| `emulado/bloco` | BOOT, FLASH, RAM | K3 under K2 | `block_ram` |
| `dispositivo/sdram` | RAM | K2 over pins | `sdram` |
| `dispositivo/sram` | RAM | K2 over pins | `sram` |
| `dispositivo/nor` | FLASH | K2 and K4 | `nor` |
| `dispositivo/flash-interna` | FLASH | K2 and K4 | `onchip_flash` |
| `dispositivo/serial` | FLASH | K2 and K4 | `serial_flash` |

The latency of a device backend, in cycles of a clock of period $T$, is

$$ n_{cycles} = \left\lceil \frac{t_{chip}}{T} \right\rceil $$

for each chip timing $t_{chip}$ in the catalog. The `emulado` backend imitates a device by copying the same $n_{cycles}$ into the `latency` of the segment in `memory`, which keeps program time comparable across boards.

### 2.1. Data width other than 32 bits

A device of width $W < 32$ delivers a word in $32/W$ accesses.

| Case | Width | Form |
| :--- | ---: | :--- |
| 16-bit SDRAM (DE0-CV, DE0-Nano, DE10-Lite, MKR Vidor) | 16 | Burst of 2 per word |
| 32-bit SDRAM (DE2-115) | 32 | Two 16-bit chips in parallel, burst of 1, 4-bit `DQM` |
| NOR FLASH of the DE2-115 | 8 | Four serial reads per word, page read |
| SRAM of the DE2-115 | 16 | Two accesses per word |

| K6 | Peripheral on the external interconnect | [ext_interconnect](../interconnect/ext_interconnect.md) |

| Realization | Debug port |
| :--- | :--- |
| Emulated RAM | Memory loader over JTAG |
| SDRAM | Debug master, the second master of the controller |
| Emulated FLASH | Port B of the storage, owned by the loader with the core stopped |
| NOR FLASH | The FLASH controller using the K4 commands |

## 4. Vendor wrappers

All vendor code lives in folders named after the vendor, with one wrapper per primitive.

| Wrapper | Varies with the family? |
| :--- | :--- |
| Block memory (`altsyncram`), one entity with generics for mode, byte mask and initialization file | Only through the family generic |
| Virtual JTAG (`sld_virtual_jtag`), one entity with generics for instance index and IR width, in Common-Components | No |
| PLL (`altera_pll` or `altpll`) | Written by the generator, per family |
| Internal FLASH (`altera_onchip_flash`) | MAX 10 only |

## 6. Internal RAM budget of the emulated backend

The `emulado` backend consumes FPGA memory blocks, and the estimator counts whole blocks, because each memory rounds up to blocks of 9 kbit (M9K) or 10 kbit (M10K).

$$ N_{blocks} = \sum_{m} \left\lceil \frac{8\,s_m}{b_{block}} \right\rceil + N_{caches} + N_{regs} \qquad u_{mem} = \frac{N_{blocks}}{N_{available}} $$

with $s_m$ the size in bytes of each emulated memory, $b_{block}$ the bits per block of the family, and the fit policy of [cabimento.md](cabimento.md) (error above $u_{mem} = 1$, warning above $0.85$).

| Board | Blocks | Bits per block |
| :--- | ---: | ---: |
| DE0-CV | 308 | 10,240 |
| DE2-115 | 432 | 9,216 |
| DE0-Nano | 66 | 9,216 |
| DE10-Lite | 182 | 9,216 |
| DE10-Nano | 557 | 10,240 |
| DE0-Nano-SoC | 246 | 10,240 |
| MKR Vidor | 56 | 9,216 |

A certification profile with 1 MB of FLASH and 1 MB of RAM only fits through the device backend, because no board holds that memory emulated.
