# C and Rust language servers

Live 0.10.1 recommends clangd for C and rust-analyzer for Rust. Use it with the
matching SDK changes; updating only the VSIX does not install native tools in
an already running container.

New Dev Containers install clangd as a container package and install its VS
Code extension. Rust setup installs `rust-src` and the `rust-analyzer` component
of the project's active Rust toolchain. The SDK selects that server explicitly:
the current marketplace extension's bundled server requires Rust 1.94+, while
the SDK toolchain is Rust 1.85.1.

**RV32: Prepare Project** regenerates the analysis settings. It adds language
extensions to existing container metadata without removing other extensions.
Rebuild the Dev Container after this preparation to install new packages and
extensions. Reload the VS Code window if an old language server is still active.

The SDK writes `.rv32/compile_commands.json` for original application C sources,
additional sources, and generated drivers. It uses the selected CPU profile,
cross-compiler and `project.include_dirs`. clangd queries only that compiler for
its target headers. Microsoft C/C++ IntelliSense is disabled in the workspace
to avoid duplicate diagnostics; the extension can remain installed.

Rust analysis follows the selected RISC-V target, enables build scripts and
procedural macros, and avoids the bare-metal `test` harness. Cargo checks only
binary targets in release mode, with one build job. rust-analyzer uses its
dedicated `target/rust-analyzer` directory. Placing its output outside Cargo's
target tree left bindgen `OUT_DIR` includes unresolved with the matching 1.85.1
server; the standard dedicated directory resolved them correctly.

Unrelated workspace settings are retained. The first overwritten settings and
editor/container metadata are backed up under `.rv32/`. Analysis files are not
rewritten on every build when their content is unchanged.

Validation used real clangd checks of the stepper C application (zero errors),
Cargo check for the Rust firmware, and an LSP session with rust-analyzer 1.85.1.
The session checked project loading, GPIO type information, navigation into
the Rust driver and navigation into the C bindings generated by bindgen.
